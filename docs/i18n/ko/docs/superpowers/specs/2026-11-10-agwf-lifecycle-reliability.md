# 수명 주기 신뢰성 명세

> 2026년 11월 10일의 과거 명세입니다. 아래 근거와 승인은 당시 작업에 적용됩니다. 현재 동작은 [운영 안내서](../../../skills/agent-workflow-v1-1/references/operations.md)를 참조하세요.

<a name="intended-result"></a>

## 목표

최초 활성화, 사용량 갱신, 재개, 정상 완료가 안정적으로 이뤄지게 합니다. 대상 실행 전에 검사를 준비합니다. 시작, 실제 중단된 워크플로의 재개, 시간 측정은 각각 관측해 결과를 보고합니다.

<a name="evidence-available-at-the-time"></a>

## 당시에 확보한 근거

- 기존 비공개 시간 진단 보고서에서 활성화 전 측정 만료를 기록했습니다. 10초를 목표로 한 두 시험은 각각 98.74초, 45.05초로 실패했습니다. 두 번째 시험의 새 실행 세대와 첫 연결은 이전에 중단된 보조 프로그램의 재개를 입증하지 못했습니다.
- 별도의 비공개 정상 흐름 보고서는 정상 시작, 43.423초 뒤의 두 번째 실제 측정, 검증된 체크포인트, 정상 완료, 프로세스 종료를 기록했습니다. 이 실행은 SAVE 중단 표시를 시험하지 않았습니다.
- 당시 `scripts/candidate.py`는 `resume` 실패 뒤 새 기술 실행 세대를 열고 제어 상태를 복원할 수 있었습니다. 첫 `activate` 또는 `bind-active-goal`에는 같은 재시도 저널이 없었습니다. 구현에는 별도 회귀 검증 근거가 필요했습니다.
- 이전 유지보수에서는 승인과 지침 사이의 충돌, 테스트 보조 함수 및 대기 관련 결함 네 가지를 수정했습니다. 해당 동작은 회귀 테스트에서 계속 다뤄야 했습니다.

<a name="requirements"></a>

## 요구 사항

1. 같은 목표와 실행에 `usage_receipt_expired`가 기록된 경우에만 기존 승인으로 첫 시작을 다시 시도합니다. 새 실제 사용량 측정, 실제 활성 목표 관측, 프로세스가 없다는 검증이 필요합니다. 새로운 사용자 인용, 새 실행 식별자, 다시 작성한 사용량 데이터는 요구하지 않습니다.
2. 한도 소진, 조기 중단, 사용자의 중단, 비활성 목표, 불확실한 프로세스 소유권, 변경된 패키지나 근거, 다른 목표는 거부합니다. Python은 일관성과 형식을 검사합니다. 호출자가 식별한 사람이나 도구를 독립적으로 인증하지 않습니다.
3. 실패한 시도는 확인 가능해야 합니다. 일부만 초기화된 실행은 활성 상태로 보이면 안 됩니다. 이후 실제 SAVE 근거를 보존합니다.
4. 첫 측정 전에 패키지와 검사를 준비합니다. 실제 관측 시각을 저장합니다. 파일을 나중에 쓰더라도 오래된 측정값이 갱신되지 않습니다. `ingest`와 실행 유지 기한 연장은 별도의 작업입니다.
5. 정상 동작에서는 실제 결정이 `CHECKPOINT_SOON`과 `SAVE_AND_STOP`을 제어합니다. 중단을 인위적으로 넣지 않습니다.
6. 최초 연결과 별도로 실제 활성화됐다가 중단된 워크플로의 재개 및 Codex Continue를 입증합니다.
7. 시간 진단을 선택했을 때만 실행합니다. 실제 Codex 이벤트 전에 검사 도구를 준비합니다. 관측이 늦거나 준비가 기한을 넘기면 통과할 수 없습니다. SAVE 요청의 제안 허용 범위는 10 ± 1초이며 실제 시간을 보고합니다.
8. 주 에이전트가 계속 호스트의 목표 도구를 호출합니다. 백그라운드 프로세스에 문서화되지 않은 호스트 접근, Codex 비공개 전송 경로, 자격 증명 읽기를 추가하지 않습니다. UI 클릭의 정확한 시각을 재려면 실제 Codex 이벤트 출처가 필요합니다.
9. 체크포인트, 프로세스 종료, 보조 프로그램 완료, Codex 목표 완료를 각각 확인합니다. 사용자 승인에 따라서만 일시 정지하고 Codex 목표 도구의 기준에 따라서만 `blocked`를 사용합니다.
10. Python 3.11 이상과 표준 라이브러리를 유지합니다. Windows 공유 실패는 프로세스 종료나 성공의 근거가 아닙니다. 기존 로컬 수정과 이전 런타임 기록을 보존하고 연결 정보를 다시 쓰지 않습니다.
