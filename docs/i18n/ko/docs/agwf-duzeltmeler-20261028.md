# 2026년 10월 28일 AGWF 유지보수

> 과거 유지보수 기록입니다. 아래 관측과 승인은 당시 작업에 해당합니다. 현재 동작은 [README](../README.md)에서 확인하세요.

여섯 역할 스킬에 각각 `agents/openai.yaml`을 두고 `allow_implicit_invocation: false`로 설정했습니다. 역할 설명은 AGWF가 준비한 작업에 적용합니다. 작업 배정이나 실제 모델과 추론 강도에 관한 근거가 없으면 역할은 중단합니다. 역할 스킬이 워크플로나 감시 프로세스를 시작하지 않습니다. 주 스킬에서는 예전에 한 프로젝트 선택이 계속 유효하다는 뜻을 주던 문구를 없앴습니다.

Windows 상태 파일에 대해 공유 읽기, 권한을 보존한 교체, 제한된 재시도 방식이 소스와 설치본에서 일치하도록 정리했습니다. `candidate.py`는 바뀌는 상태 파일도 같은 공유 읽기 방식으로 읽습니다. 외부 읽기 프로세스가 잠금을 유지하면 이전 파일이 남습니다. 잠금이 계속되면 오류입니다.

설치본이 프로젝트 체크아웃에 의존하지 않도록 컨텍스트 및 사용량 도구를 패키지의 `tools/`로 옮겼습니다. 당시 검사에서는 소스, 패키지, 설치본의 41개 파일이 일치했습니다. 루트에 있던 이전 컨텍스트 도구 사본을 제거하고 테스트 경로를 수정했습니다.

기록에는 패키지 및 도구 테스트 63개와 Windows 파일 접근 테스트 9개가 나옵니다. Windows의 9개 테스트는 `-O`와 설치 파일로도 실행했습니다. 스킬 정의 7개와 파일 해시를 검사했습니다. 빠진 역할 정책 6개를 확인하는 패키지 테스트는 수정 전에 실패했고 수정 후에는 통과했습니다.

유지보수 중 AGWF는 비활성 상태였고 스킬 7개의 설정도 계속 꺼져 있었습니다. 테스트는 임시 파일로 코어의 파일 접근을 검사했습니다. 실제 Remote 동시 사용은 시험하지 않았습니다.

당시 남아 있던 위험은 측정 때마다 두 번째 Codex 서버를 띄우는 동작, PATH에서 다른 CLI를 고르는 동작, 하위 서버의 표준 오류를 버리는 동작, 패키지 전체를 반복 점검하는 동작 등이었습니다. 첫 작업에서 Remote 문제의 원인은 밝혀지지 않았습니다. 이후 변경은 [후속 유지보수](agwf-tum-duzeltmeler-20261028.md)에 있습니다. 현재 감시 프로세스는 두 번째 Codex 서버를 띄우지 않습니다.
