# 2026년 10월 28일 AGWF 사용량 감시 후속 유지보수

> 과거 유지보수 기록입니다. [첫 유지보수 작업](agwf-duzeltmeler-20261028.md)에 이은 변경을 정리합니다. 현재 활성화 권한을 부여하지 않습니다.

| 발견 사항 | 당시 기록된 변경과 확인 근거 |
| --- | --- |
| 역할 스킬 여섯 개가 자동 선택될 수 있었음 | 역할별로 `allow_implicit_invocation: false`를 지정하고 준비된 작업에서만 실행하도록 했습니다. 패키지 테스트에서 스킬 7개를 확인했습니다. |
| 소스, 원격 저장소, 설치본이 달랐음 | 필수 도구를 패키지에 넣었습니다. 깨끗한 소스 커밋으로 빌드한 매니페스트와 ZIP을 설치 파일과 비교했습니다. |
| Windows 읽기와 쓰기가 충돌했음 | 관련 구성 요소에 공유 읽기와 파일 교체 방식을 반영했습니다. Windows 임시 파일 테스트에서 잠금, 재시도, 이전 내용 보존을 확인했습니다. |
| 측정할 때마다 두 번째 Codex 서버를 시작했음 | 해당 코드를 제거했습니다. 주 에이전트가 기존 호스트 사용량 도구를 호출하고 Python은 측정 기록을 읽습니다. 측정 테스트는 프로세스 시작을 차단합니다. |
| PATH가 다른 Codex CLI를 선택할 수 있었음 | 측정 경로에서 실행 파일 선택을 제거했습니다. |
| 오류 출력을 버렸음 | 하위 서버를 제거했습니다. 측정 오류는 진단 코드, 오류 종류, 단계가 담긴 기록을 최대 20개 남깁니다. 예상하지 못한 Python 프로세스 오류는 로컬 표준 오류에 남깁니다. |
| 두 루프가 매초 패키지를 다시 검사했음 | 상태 신호에서는 실행과 실행 세대의 식별자만 확인합니다. 전체 검사는 명령과 측정 경계에서 이뤄집니다. |
| 테스트가 가짜 서버를 사용했음 | 사용량 측정 기록의 형식을 검증하도록 바꿨습니다. 당시 임시 파일로 실제 Codex 사용량 응답을 확인한 내용도 기록돼 있습니다. |
| 역할 정책에 잘못된 임계값이 남아 있었음 | 기존 `%10`을 실제 중단 임계값인 `%20`에 맞췄습니다. 데이터 부족으로 시작을 거부한 경우 해당 활성 표시를 지웁니다. |

새 경로는 `--usage-input`을 통해 원래 관측 시각과 출처 식별자를 전달합니다. 감시 프로세스가 기록을 실행 및 실행 세대와 연결합니다. 누락, 미래 시각, 만료, 이전 시각, 다른 실행의 측정값은 거부합니다. 같은 측정값을 다시 저장해도 관측 시각은 바뀌지 않습니다. 새로운 입력이 없으면 감시 프로세스가 검사를 한 번 더 하고 SAVE_AND_STOP을 기록합니다.

주 에이전트는 기한 전에 새 관측값을 얻습니다. Python은 호스트 도구를 호출하지 않습니다. `ingest`는 데이터만 반영합니다. 활성화, 프로세스 시작, 승인, 목표 관측 갱신, 중단 해제는 각각 별도의 작업입니다.

기록에는 일반 모드와 `-O` 모드로 수행한 해당 범위 테스트 111개가 나옵니다. 이 테스트 모음에서는 실제 AGWF와 Codex 실행을 막았습니다. 패키지 빌더와 읽기 전용 도구 테스트는 허용된 자식 프로세스를 사용할 수 있었습니다. 소스 검사, 설치 해시, 비활성 스킬 설정, 깨끗한 소스로 재현한 결과는 별도로 기록했습니다.

기록에 따르면 실제 호스트 사용량 응답도 관측 시각을 바꾸거나 다른 프로세스를 시작하지 않고 측정 기록 경로로 처리했습니다. 패키지에 계정이나 개인 식별 정보는 들어가지 않았습니다. 당시 Remote 문제의 정확한 원인은 여전히 확인되지 않았으며, 실제 AGWF와 Remote를 동시에 사용하는 검사는 범위 밖이었습니다. [Codex 사용량 측정 기록 형식](../skills/agent-workflow-v1-1/references/native-usage.md)을 참조하세요.
