# 상태 호환성과 복구 범위

v1.1 런타임은 승인되고 변경 불가능한 실행 이름 공간에서 현재 schema2 상태만 받습니다. 알 수 없거나 손상되거나 구버전인 상태는 동작 중인 상태를 바꾸지 않고 거부합니다. 오래된 승인 문구, 보관된 작업 호출 기록, 유효 기간이 지난 목표 관측은 권한을 부여하지 않습니다.

고정된 진입점 `scripts/candidate.py`에는 마이그레이션 명령이 없습니다. 코어에는 구버전 상태 변환기나 이전 승인 검증기가 없습니다. 다른 설치본에서 자동으로 가져오기, 시작하기, 롤백하기를 지원하지 않습니다. 승인된 패키지 업데이트 후에는 새 실행을 시작하세요. 현재 실행의 매니페스트와 보조 프로그램 연결은 그대로 유지해야 합니다.

현재 복구는 승인된 실행의 검증된 체크포인트와 새로 받은 유효한 사용자 승인으로 진행합니다. 출처 시각, 재사용 방지를 위해 예약한 ID, 파일 무결성, 파일 작성이 멈췄다는 관측을 보존하세요. 과거 중단 또는 계속 지시는 이전 기록으로 남습니다. 보조 프로그램이 복구된 목표를 자동 활성화하지는 않습니다.

새 체크포인트의 소유자는 `agent-workflow-v1-1`입니다. 코어의 별도 기본 상태 디렉터리는 `.agent-workflow-v1-1`이고, 지원되는 고정 진입점은 `.agent-workflow-v1-1/runs/<run-id>`를 사용합니다. 이전 디렉터리 `.agent-workflow`와 `.agent-workflow-v1-0`는 가져오지 않습니다. 두 경로는 예약되어 작업 경로나 복원 대상으로 사용할 수 없습니다. 현재 스냅샷 정리 절차는 그 소유권 표시를 보존합니다. 코어 CLI를 직접 호출하면 거부됩니다.

## 사용자 설치본을 1.1 기술 식별자로 전환

1. 기존 작업 프로세스와 파일 작성자를 확인합니다. 소유한 작업만 중단하세요. 이전 설치본을 옮기기 전에 해당 실행의 중단과 실제 프로세스 종료를 확인합니다.
2. 소유권 기록을 기준으로 이전 패키지를 확인합니다. 모든 스킬 검색 디렉터리 밖에 있는 백업의 해시를 검사합니다. 기존 수정 사항을 보존한 다음 진행하세요.
3. 새 매니페스트와 외부에 보관한 해시로 `skills/agent-workflow-v1-1`에 새 패키지를 설치합니다. 이전 기술 식별자에 `--update`를 적용하지 마세요.
4. 스킬 검색 경로를 바꾸기 전에 새로 설치한 진입점에서 고유한 검사용 실행 ID로 `workflow validate`를 실행합니다. 반환된 식별자, 버전, 작업 공간, 매니페스트 해시를 비교합니다. 이 검사는 `run-binding.json`을 만들며 목표, 워크플로 상태, 감시 프로세스를 시작하지 않습니다.
5. 새 호출 이름은 `$agent-workflow-v1-1`입니다. 직접 검사가 통과하면 Codex에서 주 스킬과 역할 스킬의 경로를 새 경로로 바꿉니다. 기존 활성화 및 명시적 호출 설정과 동시에 이루어진 설정 변경을 보존하세요. 해당 프로세스를 다시 확인하고 다른 세션에서 쓰는 활성 설치본을 보존합니다. 안전하게 전환한 뒤 이전 패키지를 스킬 검색 경로 밖에 보관하고 설정과 백업을 검증합니다.
6. 과거 체크포인트, 실행 연결, 호출 기록에 저장된 식별자, 경로, 해시는 그대로 둡니다. 새 패키지로 새 실행을 시작합니다. 이어야 할 작업이 있다면 검증된 기존 산출물과 실제 현재 승인을 새 실행에 각각 전달하세요.
