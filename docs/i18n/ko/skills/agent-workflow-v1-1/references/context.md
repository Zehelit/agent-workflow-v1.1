# 현재 컨텍스트 선택 (N06)

`tools/render-active-run.py`는 소스 스킬이나 설치 스킬에서 임시 프로젝트 또는 명시적으로 고른 프로젝트를 읽습니다. 워크플로를 활성화하거나 상태를 갱신·이전·기록하지 않습니다. 실제 관측 시각을 `--as-of`로 전달하세요. 출처 생성 시각이나 원래 턴의 시각을 대신하지 않습니다. 안정적인 JSON 형식은 `context_version: 1`입니다. 상태, 출처, 참조, 관측 시각이 같으면 결과도 같습니다.

출력에는 목표와 현재 식별자, 정확한 현재 승인 또는 Codex 목표 연결, 출처와 목표의 원래 시각, 현재 목표 관측, 미완료 작업 약정과 의존성·검토 참조가 담깁니다. 실행 및 승인 관측, 장애 요인과 무효화의 반대 근거, 변경 산출물 해시, 근거 파일 참조, 다음 작업도 들어갑니다. 호출 기록 본문, 준비된 프롬프트, 전체 보고서, 완료 메시지 전문, 대화 기록, 도구 로그는 제외합니다. 승인된 작업의 약정은 원본 고정 상태에서 확인할 수 있습니다. 짧은 요약에서는 승인 상태와 정확한 근거 참조를 보여 줍니다.

참조는 정확한 `{path, sha256, kind}` 객체의 엄격한 JSON 목록이며 `task_id`를 추가할 수 있습니다. `kind`는 `evidence`, `decision` 또는 `counterevidence`입니다. 안전한 프로젝트 상대 파일 경로와 소문자 SHA-256 전체를 사용합니다. 보고서 본문은 원본 파일에 남습니다. 주 에이전트가 참조 매니페스트나 리비전을 명시적으로 바꿀 때까지 반대 근거 참조는 장애 요인으로 유지됩니다. 요약을 줄여서 지울 수 없습니다. 없거나 오래된 해시, 고정되지 않은 미지원 컨텍스트 참조, 종료 결과 근거 누락, 대기 중이거나 무효가 된 의존 관계, 거부되거나 불확실한 작업, 오래된 목표·세션 목록·사용량 관측이 장애로 드러납니다. 잘못된 원본 상태, 누락된 의존성, 잘못된 고정 참조는 정규화하지 않고 거부합니다.

검사된 요약을 사용하려면 배정 시 참조 매니페스트 JSON 자체를 변경 불가능한 `file_inputs` 항목으로 고정하세요. `prepare.current_context`에는 정확히 `{path, sha256, manifest_path, manifest_sha256}`이 들어갑니다. 보조 프로그램은 매니페스트를 작업의 타입 지정 입력과 비교하고 별도로 읽은 뒤 현재 상태와 원래 출처로 요약을 다시 생성해 전체를 비교합니다. 짧게 만든 요약에 새 해시를 붙여도 장애가 사라지거나 이전 발언의 출처가 바뀌지 않습니다. 요약 관측의 유효 기간은 0~60초입니다. 준비 과정에서 상태가 달라지므로 `dispatch-start` 전에 같은 매니페스트 해시로 요약을 다시 생성하세요. 두 번째 요약이 없거나 매니페스트를 바꾸면 거부됩니다. 기존 승인, 사용량, Codex 식별자, 슬롯, 준비한 인자, 리비전과 해시 검사가 실제 동작을 결정합니다. 결과의 `dispatch_authorized`는 항상 false입니다.

`current_context`를 쓰지 않는 명령은 기존의 명시적 출처 읽기 절차를 유지합니다. 요약 결과는 Codex 도구를 승인하지 않습니다. 주 에이전트가 현재 도구 기록과 원래 사용자 근거를 계속 확인해야 합니다. 해시는 바이트 일치를 보여 주지만 공급자를 인증하지 않습니다. 외부에서 임의로 동시에 쓰는 경우 파일 시스템 관측은 원자적 스냅샷을 제공하지 않습니다.

`cache_status`는 `unknown`, `token_measurement`는 `pending_N08`로 남습니다. 컨텍스트 선택은 소스 수준의 계약입니다. 새로운 Codex 하위 세션에서의 재구성, 캐시 효과, 토큰 절감 측정, 설치본 적용에는 각각 별도 근거가 필요합니다. 출처 참조로 실제 작업 상태를 복원하고 검토자의 반대 근거를 보존하세요.

<a name="execution-and-acceptance-n07"></a>

# 실행과 승인 (N07)

`status.task_observations`는 schema2를 `contract_version: 1`로 표현하는 읽기 전용 뷰입니다. 작업별 리비전, 관측한 실행 상태·세션·시각·유효성, 독립 승인 상태와 근거 및 검토자 식별자, 지정된 쓰기 권한이 포함됩니다. 실행 관측이 오래됐거나 없으면 알 수 없는 것으로 표시합니다. 최신 세션 목록에서 관측한 done, idle, stopped는 기존 계산에 따라 활성 슬롯을 돌려줍니다. 산출물을 승인하는 동작은 아닙니다. 독립 승인이 대기 중인 동안 구현 담당자는 쓰기 권한을 유지합니다. 열린 세션 수 제한이 있으면 관측된 열린 세션을 따로 셉니다.

검토자는 더 이상 쓰고 있지 않은 작성자의 정확한 리비전과 산출물 해시를 고정합니다. 검토 작업은 자신이 검토하는 작성자의 승인에 직접 또는 간접적으로 의존할 수 없습니다. 승인 의존성과 검토 관측 연결은 별도 목적입니다. 검토가 진행되는 동안 작성자는 대기 중입니다. 승인 시 이미 지원하는 선택적 `review` 필드에 독립적으로 승인된 검토 작업을 기록하고, 서로 다른 세션, 대상 리비전, 입력 약정, 정확한 산출물 해시를 확인합니다. 바이트나 리비전 변경 또는 무효화 이후 바이트를 예전으로 되돌리는 것으로 이전 검토를 되살릴 수 없습니다. 검토자 연결 기록이 남지 않은 과거 schema2 승인은 `historical_unrecorded`로 표시하며 소급해 독립적으로 확인됐다고 하지 않습니다.

작성자와 검토자의 Codex 세션 식별자가 서로 다르고 비어 있지 않아야 하며, 배정과 결과 기록의 검토 해시도 일치해야 합니다. 표현과 승인 의존성 검사에서 같은 판단 기준을 사용합니다. 불완전한 과거 승인은 `historical_unrecorded`로 읽을 수 있지만 요약 사용 여부와 관계없이 prepare, record, dispatch-start에서 새 종속 작업을 열 수 없습니다. 요약에는 `DEPENDENCY_NOT_ACCEPTED`가 들어갑니다. prepare 이후 검토자 연결이나 Codex 식별자를 잃어도 실제 배정은 차단됩니다. 과거 식별자를 추정하거나 조용히 이전하지 않습니다.

기존 선택적 저장 필드를 사용하는 추가 뷰이며 schema2 자체는 바뀌지 않습니다. 이전 스키마는 거부하고 가져올 수 없습니다. 현재 승인과 승인된 런타임 연결이 계속 기준입니다. 요약은 어느 쪽도 활성화하거나 대체하지 않습니다.

# 인계 전 작성자 검사

`tooling/check-producer.py`는 소스 개발 단계의 검사입니다. 체크아웃에서 함께 제공되는 Python과 `-X utf8 -B`로 일반 모드 한 번, `-O` 모드 한 번 실행하세요. 소스 테스트가 필요하므로 설치 런타임 명령에는 포함하지 않습니다. 변경 경로와 공유 API를 선언하세요. 고정된 선택 목록은 코어, 입력, 승인, 목표, 조율 회귀 검사와 새 컨텍스트·승인 실패 검사, A04/A09/A11의 알려진 반례를 재사용합니다. A11 과거 통합 검사 도구는 임시 소스 사본에서 후보 워크플로 해시로 메모리 안에서 다시 검증합니다. 그 도구의 원래 바이트는 보존하고 두 의존성의 해시를 보고합니다. 변경하지 않은 감시나 브라우저 전체 테스트를 뜻하지 않습니다.

기계 판독 결과는 후보의 고정 입력(소스, 테스트, 역할 정의)과 고정 목록에 없더라도 변경 대상으로 선언한 Markdown을 포함해 모든 변경 파일의 합집합을 고정합니다. 경로는 실제로 있는 정규화된 프로젝트 상대 파일이어야 하며, 상위 탐색, 절대 경로, 드라이브 경로, 별칭, 링크, 프로젝트 밖 경로를 피해야 합니다. 선택 테스트 전후에 전체 합집합의 해시를 계산합니다. 선언한 파일이 중간에 바뀌면 PASS를 막고, `--expected-pins`는 전체 집합과 일치해야 합니다. 검사는 선택 목록, 건수, 실패, 소스 안정성을 기록하며 항상 `independent_acceptance: false`를 반환합니다. 실패한 테스트, 빠진 선택 항목, 변경된 해시, 잘못된 거부 메타데이터는 작성자 검사를 차단합니다. 작성자가 종료한 뒤 중요한 결과의 독립 검토를 진행합니다.

선택적 거부 메타데이터는 정확히 `rejections`와 `rework_seconds`입니다. 없으면 관측한 거부 목록은 비어 있고 비용은 알 수 없습니다. 비용을 0으로 가정하지 않습니다. 각 거부에는 결함 ID와 종류, 재현 참조, 수정 담당자 한 명과 집중 검토자 식별자, 리비전 및 정확한 소스 해시가 있습니다. 수정 담당자가 자신의 결과를 검토할 수 없습니다. 같은 종류가 두 번째 거부되면 짧은 `root_plan_correction`을 추가합니다. 주 에이전트가 계획 결정을 맡고 수정 작성자 한 명과 새 독립 검토를 배정합니다. 아키텍트나 팀 계층은 자동으로 추가하지 않습니다.
