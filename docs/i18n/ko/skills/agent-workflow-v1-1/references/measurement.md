# 지정 범위에서 Codex 사용량 측정

N08은 공개 메타데이터를 기계적으로 기록합니다. 모델을 호출하거나 한도 사용량과 가격을 할당하지 않습니다. 이를 승인하기 전에 작성자의 테스트와 메타데이터 재구성 결과를 독립적으로 검토해야 합니다. 새 컨텍스트와 긴 컨텍스트 비교, 캐시 동작, 동등한 조건의 비용 시험, 설치본 도입은 각각 확인해야 합니다.

소스나 설치본의 스킬 디렉터리에서 `python -X utf8 -B tools/extract-usage.py --manifest MANIFEST --output NEW_JSON`을 실행하세요. 도구와 `tools/telemetry.schema.json`은 스킬 매니페스트에 고정됩니다.
API는 `extract(manifest)`와 `publish(document, new_path, canaries=())`입니다.
출력은 키를 정렬하고 구분자를 최소화하며 끝에 LF를 한 개 둔 정규 UTF-8 JSON입니다. 기존 출력 파일은 덮어쓰지 않습니다. `--canary-file`은 공개되면 안 되는 정확한 문자열을 담은 비공개 JSON 배열을 읽습니다. 이 배열을 근거에 복사하지 않습니다. 출력 파일을 열기 전에 밖으로 나갈 모든 문자열과 키를 확인합니다. 오류에는 고정 사유 코드만 포함합니다.

매니페스트에는 정확히 `runs`, `comparison_pairs`, `checks`, `evidence_pins`가 있습니다. 각 실행에는 `run_id`, `sources`, `phases`, `coverage_gaps`가 있습니다. 출처는 `source_id`, `path`, `thread_id`, `session_id`, `task_id`, `agent_path`, 양끝을 포함하는 `ranges`, `requested_model`, `requested_effort`, `main_client_selected`를 선언합니다. `prefix_bytes`와 `sha256`은 선택입니다. 값을 지정하지 않으면 파일을 열 때 기록하고, 지정했다면 실제 값이 일치해야 합니다. 파일에 후속 기록을 추가한 뒤에도 재현하려면 바이트 제한과 SHA-256을 지정하세요.
완전한 레코드로 구성된 JSONL의 처음 일부만 받습니다. 엄격한 JSON 처리는 중복 키와 유한하지 않은 숫자를 거부합니다. 범위는 순서대로 나열되며 겹치면 안 됩니다. 출처와 헤더의 식별자가 명확해야 하고 응답 시각은 역행하지 않아야 합니다. 범위가 빠지면 매니페스트를 거부합니다. 누락 범위나 재시작이 있으면 토큰 합계는 null로 두고 사유를 기록합니다.

응답별 메타데이터에는 `token_usage_record.usage`를 기준으로 사용합니다. 응답 ID는 채팅, 세션, 턴, 출처 범위에서 한 번만 셉니다. 서로 다른 내용을 가진 중복 레코드, 외부 범위, 필드 누락, 잘못된 부분합은 사유가 붙은 null로 남습니다. 선택 범위 경계를 넘어 과거 응답이 재사용돼도 새 완료 건으로 세지 않습니다. 고정된 파일 앞부분의 다른 위치에 같은 ID의 잘못된 관측이 있으면 선택 구간의 재사용도 무효입니다. 앞쪽에서 발생한 잘못된 관측도 해당합니다. 같은 ID의 중복을 포함해 선택한 모든 시각은 최신 시각 기준을 갱신합니다. 응답을 중복 집계하지 않더라도 시간순 검사는 각 관측에 적용합니다.
토큰 수는 불리언을 제외한 0 이상의 정수입니다. `total_tokens`는 입력과 출력의 합입니다. 캐시된 입력과 캐시에 쓴 입력은 입력의 부분집합이고, 추론 출력은 출력의 부분집합입니다. 각 부분집합을 원래 입력·출력에 더하지 않습니다. 캐시 제외 입력은 입력에서 캐시된 입력을 뺀 토큰 수입니다. 요금 지표가 아닙니다. 캐시 관련 원인을 알 수 없으면 미확인 상태로 남깁니다.

`event_msg.info.total_token_usage`와 `token_usage_record.thread_token_usage`는 서로 독립된 누적 데이터입니다. 기준, 초기화, 누락 사유를 명시하고 차이는 null로 두며 두 값 모두 진단에만 씁니다. 응답별 집계를 대신하지 않고 합치거나 교차 차감하지 않습니다. 초기화 진단으로 독립된 완전한 응답별 레코드가 무효가 되지는 않습니다. 응답 수는 완료 기록의 관측된 ID 수이며 청구된 요청 수와는 별개입니다.

비공개 대화 기록, 추론, 도구 입출력 본문, 계정·프로필·설정 필드, 내용을 해석하지 않는 메시지는 출력 구조에서 제외합니다. 로컬 비공개 도구 값은 표시 크기를 계산하고 Codex 데이터 경계를 식별할 때만 읽습니다. 밖으로 내보내거나 숨은 추론으로 분류하거나 복호화하지 않습니다. 도구 출력은 고유 호출 ID, 범위 안의 대응 호출, 올바른 시간순을 요구합니다. 문자열은 원본 UTF-8 바이트 수로, 구조화된 값은 삽입 순서를 유지한 간결한 JSON을 `ensure_ascii=False`로 UTF-8 인코딩한 바이트 수로 잽니다. 승인된 N05 표현 규칙을 따릅니다. 이 값은 바깥 JSONL 직렬화 크기, 네트워크 전송량, 청구 바이트와 다릅니다.

정확한 Codex 요청 기록에서 요청한 모델과 추론 강도를 가져옵니다. 주 클라이언트는 사람이 선택하므로 주 클라이언트의 요청 필드는 null로 유지합니다. 턴 컨텍스트에서 관측한 모델과 추론 강도는 출처에 한계가 있는 관측 설정이며, 공급자가 실행한 실제 모델을 증명하지 않습니다. 관측이 누락된 필드, 실제 모델, 비용, 통화는 이유와 함께 null로 둡니다. 요금표, Standard 대리값, 캐시 실패 이유, 동작 한 건당 5시간 구간 소비량을 추론하지 않습니다. 비교에는 경과 시간과 원시 토큰 변화가 남습니다. 실제 비용 차이는 알 수 없습니다. 합성 비용 반례는 같은 통화를 명시해 더 빠르면서 비싼 대안도 결과에 남는지만 확인합니다. 실제 공급자 청구 근거는 아닙니다.

단계는 `implementation`, `repair`, `independent_review`, `external_wait`, `closure`입니다. 작업과 출처, 캡처한 시작과 종료, 권한 식별자를 각각 갖습니다. 관측에 빈틈이 있으면 기간은 null입니다. 수명 주기 구간에는 대기와 조회 시간이 포함되므로 실제 계산 시간을 입증하지 못합니다. `agent_active_seconds_sum`은 null로 둡니다.
`observed_agent_interval_seconds_sum`은 에이전트별로 겹치는 구간을 합친 다음 각 에이전트의 시간을 더합니다. `observed_wall_union_seconds`는 모든 에이전트의 구간을 한데 합칩니다. 외부 대기는 에이전트별 합산에서 제외됩니다. 구간이 겹치면 두 결과는 다릅니다. `coverage_complete`에는 선언한 누락, 토큰 범위 오류, 도구 관측 누락, 단계 관측 또는 타입 누락이 없어야 합니다. 완전하지 않으면 `complete_wall_union_seconds`가 null이고 단계 사유에 `run_coverage_incomplete`가 남습니다. 이 값들은 유효하게 한정한 토큰 합계와 관측한 실시간·수명 주기 구간의 합집합과는 별개입니다. 단계의 작업과 출처 연결은 출처와 맞아야 합니다. 한쪽이 누락됐어도 알려진 시작 또는 끝은 올바른 시각이어야 합니다. 관측이 부족하면 기간은 계속 null입니다. 관측 구간을 합쳐도 전부 관측하지 않은 프로젝트의 전체 시간은 알 수 없습니다.

앞으로 동일 작업을 새롭고 간결한 Codex 컨텍스트와 긴 공개 기록으로 비교하려면 주 에이전트가 두 실행 ID, 각 조건의 주 세션 표시 범위, 정확한 하위 세션 헤더 출처, 구현·수정·검토·대기·종료에서 관측한 구간을 매니페스트에 적고 `comparison_pairs: [["fresh_compact", "public_long_history"]]`를 지정합니다.
캡처가 끝난 Codex 기록의 `prefix_bytes`와 `sha256`을 사용합니다. 요청 모델과 강도는 도구 기록을, 원시 입력 및 캐시 포함·제외 입력과 출력은 응답별 기록을 참조합니다. 출처는 완료된 하위 세션 앞부분 전체를 `ranges: [[1, RECORD_COUNT]]`로 포함할 수 있습니다. 도구 바이트를 재려면 주 세션 표시 범위에 호출과 대응 출력이 모두 들어야 합니다. 완료나 단계 관측이 빠지면 `coverage_gaps`와 끝점이 null인 구간에 남기고 추정하지 않습니다. `extract(manifest)`는 조건별 메타데이터를 연결하고 토큰 차이를 계산합니다. `publish`는 필드가 닫힌 스키마, 의미 관계, 설정한 탐지 문자열을 검사한 뒤 결과를 확정합니다. 의미 검증기는 고유 응답 합계, 원시 값 및 부분집합 계산, 출처와 실행 건수, 도구 바이트 합계와 매핑, 출처·범위 연결, 진단 전용 데이터, 단계 시간과 합집합, 범위·null·사유의 관계, 비교를 다시 계산합니다. 문서 구조가 올바르더라도 이 관계를 우회할 수 없습니다. 검증은 출력 생성 전에 끝납니다. 문서 내부 관계만 확인하며 원래 메타데이터의 출처를 인증하지 않습니다.
두 경우에 실제로 같은 작업을 했는지, 컨텍스트를 어떻게 처리했는지, Codex 캐시를 어떻게 해석할지는 주 에이전트가 관리하는 별도 절차와 독립 검토가 필요합니다. 추출기는 Codex 읽기 세션을 만들거나 실험을 승인하지 않습니다.

`telemetry.schema.json`은 모든 공개 객체에 추가 필드를 허용하지 않습니다. 외부 의존성이 없는 검증기는 문서에 적힌 표준 JSON Schema의 부분집합을 구현하고 알 수 없는 키워드를 거부합니다. 일반 및 최적화 모드 테스트는 실제 추출·출력 경로를 사용합니다. 운영 검증에 assert를 쓰지 않습니다. 근거 해시는 정확히 읽은 파일 앞부분을 식별합니다. 바뀔 수 있는 파일 전체를 증명하지 않습니다. 메타데이터 해시는 바이트를 확인하며, 공급자 청구, 기록의 진위, 실제 모델 주장은 증명하지 못합니다.

이 도구는 과거 평가에 의존하지 않습니다. 측정할 때마다 근거를 고정한 자체 매니페스트를 준비하고 독립 승인을 받으세요.
