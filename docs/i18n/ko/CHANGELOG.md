# 변경 이력

이미 존재하는 버전의 기록입니다. 소스 체크아웃과 승인된 빌드 기록으로 정확한 패키지를 식별할 수 있습니다.

<a name="11--2026-11-10"></a>

## 1.1 — 2026년 11월 10일

<a name="added"></a>

### 추가

- activate 또는 bind-active-goal의 첫 실행 시도를 지속적으로 기록합니다. 안전한 재시도에 쓸 실패 기록의 SHA-256은 패키지 외부에 보관합니다.
- 후보 프로그램의 수명 주기 작업을 한 작성자만 수행할 수 있도록 해당 실행이 소유하는 잠금을 추가했습니다.
- 준비, 시작, 관측 갱신, 중단 후 재개, 정상 완료를 위한 tooling/run-lifecycle-check.py가 추가됐습니다.
- 명시적으로 선택하는 timed-test 모드에서 SAVE, 체크포인트, 중단 시각을 각각 기록하고 늦은 이벤트를 분류합니다. 이 도구는 Codex가 실제로 일시 정지됐다는 근거를 제공하지 않습니다.
- 상태 요약에 실제 측정 시각, 기한, 간격, 먼저 갱신할 권장 시각을 표시합니다.
- 프로젝트 목적, 아키텍처, 워크플로, 오케스트레이션 다이어그램, 수동 및 에이전트 설치 안내, 수명 주기 안내서를 추가했습니다.

<a name="fixed"></a>

### 수정

- 사용량 관측값이 만료됐을 때 동일한 승인된 활성 목표에서 검증된 재개가 가능합니다. 실제 한도 소진과 사용자가 요청한 중단은 각기 다른 절차를 따릅니다.
- 첫 시작 실패 후 재시도하는 동안 기존 범위, 이전 SAVE 근거, 패키지 연결을 보존하고 프로세스가 종료됐는지 확인합니다.
- 주간 구간에 한시적 예외를 두면 코어와 감시 프로세스에 동일하게 적용합니다. 실제 관측값은 덮어쓰지 않습니다.
- 한정된 횟수의 재시도로 확인된 Windows 공유 및 잠금 읽기 오류에 대응합니다. 지속되거나 분류되지 않은 오류는 그대로 드러납니다.
- 측정값 갱신, 실행 유지 기한 연장, 중단 후 관측값 유효성 요구 사항을 명확히 했습니다.
- 오래된 테스트 보조 함수의 인자와 프로세스·파일을 기다리는 방식을 고쳤습니다.

<a name="compatibility-and-evidence"></a>

### 호환성과 근거

- 호출 이름, 설치 경로, 런타임 이름 공간이 함께 1.1로 바뀝니다. 각각 `$agent-workflow-v1-1`, `agent-workflow-v1-1/`, `.agent-workflow-v1-1/runs/`입니다.
- 새 매니페스트는 이전 기술 식별자를 거부합니다. 과거 실행은 기록으로 보존하고 자동으로 연결을 바꾸지 않습니다. 이전 이름 공간은 소유 확인과 복원을 위해 예약해 둡니다.
- 업데이트는 실행의 변경 불가능한 패키지 연결을 다시 쓰지 않습니다. 새 패키지를 승인한 뒤 새 실행을 시작하세요.
- Python 3.11 이상과 표준 라이브러리만 필요합니다. 감시 프로세스는 Codex 사용량 도구에 직접 접근하지 않고 보조 Codex 서버도 시작하지 않습니다.
- 격리 테스트는 합성 호스트 관측값과 실제 Python 작업 프로세스를 사용합니다. 실제 Remote, Continue, 인터페이스의 시간 측정에는 별도 근거가 필요합니다.
- 이 버전은 소스 커밋으로 기록됐습니다. GitHub 릴리스와 태그는 당시 기록된 공개 범위 밖에 있었습니다.

<a name="10--previous-source-version"></a>

## 1.0 — 이전 소스 버전

- 매니페스트 해시로 고정된 후보 진입점, 타입이 지정된 워크플로 상태, 역할 문서, 파일 소유권 및 슬롯 검사.
- 모델을 쓰지 않는 내장 감시 프로세스, 체크포인트와 복원, 지속적인 조율 저널, 결정적 패키지 생성.
- 과거 기록은 이에 대응하는 GitHub 릴리스나 태그의 존재를 주장하지 않습니다.
