# 対象範囲を指定したネイティブ使用量の計測

N08 は公開可能なメタデータを機械的に記録します。モデルを呼び出したり、クォータの消費量や料金を割り当てたりすることはありません。生成側のテストとメタデータの再構成は、受け入れ前に独立したレビューで実質的な結果まで確認する必要があります。新規コンテキストと長い履歴の比較、キャッシュの挙動、同条件での費用比較、インストール済み環境への採用には、それぞれ個別の確認があります。

ソースのチェックアウトまたはインストール先のスキルディレクトリで `python -X utf8 -B tools/extract-usage.py --manifest MANIFEST --output NEW_JSON` を実行します。ツールと `tools/telemetry.schema.json` はスキルのマニフェストで固定されています。
API は `extract(manifest)` と `publish(document, new_path, canaries=())` です。
出力は、キーをソートし、区切りを詰め、末尾に改行 LF を一つ付けた正規形の UTF-8 JSON です。既存の出力ファイルは上書きしません。`--canary-file` は、混入を検知するための文字列を完全一致で指定した非公開の JSON 配列を読み込みます。この配列は証跡にコピーされません。出力先を開く前に、書き出すすべての文字列とキーを確認します。エラーには固定の理由コードのみが含まれます。

マニフェストのキーは `runs`、`comparison_pairs`、`checks`、`evidence_pins` の四つです。
各実行には `run_id`、`sources`、`phases`、`coverage_gaps` があります。各ソースは `source_id`、`path`、`thread_id`、`session_id`、`task_id`、`agent_path`、両端を含む `ranges`、`requested_model`、`requested_effort`、`main_client_selected` を宣言します。`prefix_bytes` と `sha256` は任意です。固定情報の指定がなければファイルを開く際に取得し、指定があれば一致を求めます。追記後にも同じ範囲を再現するには、バイト上限と SHA-256 を指定してください。
JSONL はレコードが途中で切れていない先頭部分だけを受け付けます。厳密な JSON として重複キーや有限でない数値を拒否します。範囲は順序どおりで重ならず、ソースおよびヘッダーの識別情報が明示され、応答時刻が逆行していないことが条件です。範囲の指定がなければマニフェストを拒否します。範囲内の捕捉漏れや再起動があればトークン合計は null となり、理由を記録します。

応答ごとのメタデータには `token_usage_record.usage` を使います。応答 ID はスレッド、セッション、ターン、ソースの範囲を踏まえて一度だけ数えます。重複する記録に食い違いがある場合、別の範囲に属する場合、フィールドが欠けている場合、部分集合の合計が不正な場合は null とし、理由を残します。選択した境界をまたいで過去の応答が再利用されても、新しい完了としては扱いません。固定した先頭部分の別の位置に同じ ID の不正な記録があれば、より早い記録も含め、選択範囲内での再利用を無効とします。選択した記録の時刻は、同じ ID の重複も含めてすべて時系列の確認に使います。重複排除で時系列から観測点を除くことはありません。
トークン数には、真偽値を除く非負整数を使います。`total_tokens` は入力と出力の合計です。キャッシュ済み入力とキャッシュ書き込み入力は入力の部分集合で、推論出力は出力の部分集合です。入力・出力の総数に部分集合を足しません。キャッシュ分を除いた入力は、入力からキャッシュ済み入力を引いたトークン数です。請求額を表す数値ではありません。キャッシュに関する原因が記録されていない場合は、不明のままとします。

`event_msg.info.total_token_usage` と `token_usage_record.thread_token_usage` は互いに独立した累積系列です。
どちらも診断用として差分を null にし、基準値、リセットまたは欠落の理由を明示します。使用量の代替根拠には使わず、系列の結合や系列をまたぐ引き算もしません。リセットの診断があっても、独立した応答ごとの記録が完全なら有効です。応答数は完了の計上に使われる観測済み ID の件数です。請求されたリクエストの件数は測りません。

非公開の会話ログ、推論、ツール入出力の本文、アカウント・プロフィール・設定のフィールド、内容を解釈しないメッセージは、出力の構造から除外されます。ローカルの非公開ツール値を読むのは、表現の長さを計算し、ネイティブな境界を見つける場合に限ります。公開出力への書き出し、非公開推論としての分類、復号は行いません。ツール出力には、一意な呼び出し ID、範囲内の対応する呼び出し、矛盾のない時系列が必要です。文字列は元の UTF-8 バイト長、構造化された値は挿入順を保ったコンパクトな JSON を `ensure_ascii=False` で UTF-8 にした長さを使います。この長さは受け入れ済みの N05 の表現規則に従います。外側の JSONL レコードのシリアライズ長、通信量、請求上のバイト数とは異なります。

要求したモデルと推論強度は、対応するネイティブリクエストの記録から取得します。メインクライアントは人が選択するため、メインの要求フィールドは null のままです。ターンのコンテキストにあるモデルと推論強度は、取得元に制約がある観測設定です。プロバイダーが実際に使用したモデルを証明するものではありません。未観測の設定、実効モデル、費用、通貨は理由付きで null とします。料金表や Standard を代替値として適用したり、キャッシュミスの原因や一操作あたりの 5 時間枠の消費を推測したりすることはありません。比較には経過時間と生のトークン数の差を残します。実際の費用差は不明です。同じ通貨を明示した合成データの反例は、速い一方で費用が高い選択肢も比較に現れることを確かめるためだけに使います。プロバイダーからの実際の請求を示す証跡ではありません。

フェーズは `implementation`、`repair`、`independent_review`、`external_wait`、`closure` です。フェーズごとにタスク、ソース、観測した開始と終了、権限の識別子を記録します。捕捉が欠ければ所要時間は null になります。ライフサイクルの区間には待機やポーリングが含まれ、実際の計算時間を示さないため、`agent_active_seconds_sum` は null のままです。
`observed_agent_interval_seconds_sum` はエージェントごとに重複を除いた区間長を集計します。`observed_wall_union_seconds` は全エージェントを通して区間の重複を除いた時間です。前者の集計からは外部待機を除きます。区間が重なる場合、この二つの値は異なります。`coverage_complete` が成立するには、宣言済みの欠落、トークン範囲の不整合、ツールの捕捉漏れ、フェーズ捕捉や型の不備が一つもないことが必要です。捕捉範囲が不完全な場合、`complete_wall_union_seconds` は null のままで、フェーズの理由に `run_coverage_incomplete` が入ります。これらは、有効な範囲内のトークン合計や、観測された実経過区間およびライフサイクル区間の和集合とは独立しています。フェーズのタスクとソースの対応は、対象ソースと一致させます。片側が欠けていても、判明している開始・終了の値は有効なタイムスタンプである必要があります。捕捉漏れがあれば所要時間は null です。観測できた区間の和集合から、観測できていないプロジェクト全体の所要時間は分かりません。

今後、同じ仕事を新規の短いネイティブコンテキストと公開の長い履歴で比べる場合、ルートは二つの異なる実行 ID、各条件におけるメインのマーカー範囲、子エージェントのヘッダーに対応する正確なソース、実装・修正・レビュー・待機・終了の観測区間をマニフェストに記録し、`comparison_pairs: [["fresh_compact", "public_long_history"]]` を指定します。
ネイティブでの捕捉が完了したら、その `prefix_bytes` と `sha256` を使います。要求モデルと推論強度はリクエスト記録から取得します。生の入力、キャッシュ済み入力、キャッシュ分を除いた入力、および出力は、ネイティブの応答別記録を使います。各ソースは完成した子エージェントの先頭部分全体を `ranges: [[1, RECORD_COUNT]]` で指定できます。ツールのバイト数を測るには、メインのマーカー範囲に呼び出しと対応する出力の両方を含めます。終了またはフェーズを捕捉できなければ、`coverage_gaps` と片端が null のフェーズ区間に記録します。推定値は使いません。`extract(manifest)` は条件ごとに関連付けたメタデータとトークン差を生成し、`publish` は閉じたスキーマ、意味上の関係、設定済みの検知文字列を検証してから結果を確定します。意味検証では、一意な応答の合計、全体と部分集合の計算、ソースと実行の件数、ツールのバイト数と対応付け、ソースと範囲の関連、診断専用の系列、フェーズの長さと区間の和集合、捕捉範囲・null・理由の関係、比較を再計算します。構造上有効な文書であっても、変更によってこれらの関係を回避することはできません。検証は出力を作成する前に終わります。確認対象は文書内の整合性です。元のメタデータの出所までは証明しません。
二つの試行が同等の仕事か、コンテキストをどう扱ったか、ネイティブキャッシュをどう解釈するかについては、別途ルートが管理する手順と独立したレビューが必要です。抽出ツールはネイティブの読み取りセッションを作成せず、実験の受け入れも宣言しません。

`telemetry.schema.json` は公開オブジェクトすべてで未定義のフィールドを許可しません。依存関係のないバリデーターは、明記された標準 JSON Schema の部分集合を実装し、未知のキーワードを拒否します。通常モードと最適化モードのテストは、実際に抽出と書き出しの経路を通ります。本番の検証は assert に依存しません。証跡の固定情報は、実際に走査した先頭部分の正確な範囲を示します。追記可能なファイル全体についての主張ではありません。メタデータの固定情報で確認できるのはそのバイト列です。プロバイダーの請求、リクエスト記録の真正性、実効モデルの主張は確認できません。

このツールは過去の評価に依存しません。計測を新たに行うたびに、固定情報を含む専用のマニフェストを用意し、独立した受け入れ判定を受ける必要があります。
