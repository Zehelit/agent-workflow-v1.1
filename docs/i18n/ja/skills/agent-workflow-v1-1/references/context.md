# 現在のコンテキストの選択（N06）

`tools/render-active-run.py` は、ソースとインストール済みスキルの双方で、使い捨てまたは明示的に選んだプロジェクトを読みます。有効化、更新、移行、状態書き込みは行いません。実観測時刻を `--as-of` に渡し、原資料の作成時刻や元ターンの時刻は変えません。固定 JSON 契約は `context_version: 1`。状態、ソース、参照と観測時刻が同じなら出力も同じです。

出力には目標、現在の識別情報、正確な許可またはネイティブ紐付け、元資料と目標の時刻、現観測、未完了タスクの契約、依存と審査対象の固定値、実行と受け入れ、阻害要因と反証、変更ファイルのハッシュ、証拠参照、次の行動が入ります。受領記録本文、作成済みのプロンプト、全報告、終了タスクの最終文、会話やツールのログは含めません。受け入れ済みの契約は固定した元状態にあり、短い表示には承認と正確な証拠参照を残します。

参照は `{path, sha256, kind}` の厳密な JSON 配列で、`task_id` を追加できます。`kind` は `evidence`、`decision`、`counterevidence`。安全で正確なプロジェクト相対ファイルを指定し、SHA-256 は完全な小文字です。報告本文はソースに残します。反証はメインが参照マニフェストやリビジョンを意図的に更新するまで阻害要因です。要約を削っても消せません。ハッシュの欠落や古さ、未固定で非対応の文脈参照、終端証拠なし、未完了または無効な依存、拒否や結果不明、古い目標・一覧・使用量は明示されます。状態の破損、依存の欠落、不正な固定値は拒否し、自動補正しません。

制約付きの要約を使うなら、割り当て時に参照マニフェストを変更不能の `file_inputs` として固定します。`prepare.current_context` は正確に `{path, sha256, manifest_path, manifest_sha256}` を持ちます。ヘルパーは型付きの固定値とマニフェストを照合し、別に読み、現在状態と元の出典から再生成した全体を照合します。要約を削って固定値を付け直しても、阻害要因を消したり旧発言を新規扱いしたりできません。観測は 0～60 秒以内です。準備で状態が変わるため、同じマニフェストで `dispatch-start` 前に再要約します。欠落やすり替えは拒否されます。実際の操作には、元々の許可、使用量、ネイティブ識別、容量、準備済み引数、版とハッシュが必要です。表示の `dispatch_authorized` は常に false です。

`current_context` を使わないコマンドは明示的なソース読み取りを継続します。表示ではネイティブ操作を許可できません。メインは実際の記録と人間の許可を確認します。ハッシュはバイトの一致であり、プロバイダー認証ではありません。ファイル観測は任意の外部書き込みに対する原子的なスナップショットではありません。

`cache_status` は `unknown`、`token_measurement` は `pending_N08` のままです。選択的コンテキストはソース契約です。新規子エージェントでの復元、キャッシュやトークン節約、導入実績は個別に確認してください。実行可能な状態をソース参照から組み立て、審査の反証を削除しません。

<a name="execution-and-acceptance-n07"></a>

# 実行と受け入れ（N07）

`status.task_observations` は schema2 を読み取り専用で表示する `contract_version: 1` です。タスク別にリビジョン、観測された実行状態・セッション・時刻・鮮度、独立審査結果と根拠、審査担当、書き込み所有を示します。実観測が古い、または欠けていれば不明です。ネイティブ done、idle、stopped は最新一覧を基に実行枠を空けますが、成果物は合格しません。独立審査待ちなら作者が書き込み権を保持します。開放セッションの任意の上限は別に数えます。

検証者は書き込み停止済みの作者の正確な版とハッシュを固定します。検証者はその作者の合格へ直接・間接に依存できません。依存の承認と審査の観測は別です。作者側は審査中も保留です。受け入れは既存の `review` に独立して合格した検証者を置き、別セッション、版、入力契約、出力を照合します。編集や版変更で審査が失効し、元ファイルに戻しても復活しません。審査者への記録がない過去の合格は `historical_unrecorded` です。独立審査済みにはしません。

独立性には作者と検証者の空でない別々のネイティブセッションと、割り当てと記録の出力ハッシュの一致が必要です。表示と依存の判定は同じ条件です。古い不完全な `historical_unrecorded` は読み取れますが、準備・記録・割り当て開始時の新規依存を満たしません。要約に `DEPENDENCY_NOT_ACCEPTED` が出ます。準備後に審査者やセッション識別を失っても実行は止まります。過去の識別情報を推定・自動移行しません。

これは既存の任意フィールドを利用する追加表示です。schema2 は変わりません。旧状態は拒否して取り込みません。現在の許可と承認済み紐付けは引き続き有効で、要約が有効化や代替を行うことはありません。

<a name="producer-handoff-gate"></a>

# 成果物提出前の確認

`tooling/check-producer.py` はソース開発の確認です。作業コピーから同梱 Python と `-X utf8 -B` を使い、通常と `-O` で分けて実行します。ソーステストが必要なため、導入済みの実行用コマンドではありません。変更パスと共有 API を指定します。固定セレクターはコア、入力、許可、目標、調整、コンテキスト、審査の回帰や A04/A09/A11 の反例を使います。A11 の旧ランナーは使い捨てのソースコピーで candidate ハッシュをメモリー内で再検証します。歴史的ランナーのバイトを保持し、両依存の固定値を報告します。この確認で監視やブラウザーの全体試験を代替しません。

機械結果は、既定の candidate 入力（ソース、テスト、ロール）と、変更として宣言した全ファイルを固定します。既定リスト外の Markdown も含みます。既存の正規化されたプロジェクト相対ファイルを使い、越境、絶対パス、ドライブ、別名、リンクを拒否します。テスト前後で集合全体をハッシュ化し、宣言したファイルが変わると失敗します。`--expected-pins` は集合全体と一致が必要です。セレクター、件数、失敗とソースの安定性を記録し、常に `independent_acceptance: false` を報告します。テスト失敗、セレクターの欠落、ハッシュ変更、不正な却下メタデータは合格を妨げます。作者の終了後に独立レビューを行います。

却下の任意メタデータは `rejections` と `rework_seconds` だけです。欠けている場合は観測できた却下が空で費用が不明です。却下ごとに欠陥 ID、種別、再現の参照、修正者一人と重点審査者、版およびソースハッシュを記録します。修正者は自分を審査しません。同じ種類の却下が二回なら、短い `root_plan_correction` も保存します。メインが方針を直して一人の修正担当と新たな重点審査を割り当てます。自動で組織階層やチームを追加しません。
