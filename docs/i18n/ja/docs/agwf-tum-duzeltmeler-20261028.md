# 2026 年 10 月 28 日の AGWF 監視保守の続き

> [最初の保守](agwf-duzeltmeler-20261028.md)に続く過去の記録です。現在の起動許可ではありません。

| 課題 | 当時の対策と証拠 |
| --- | --- |
| 六つのロールを自動選択できた | `allow_implicit_invocation: false` と準備済み割り当ての制限を追加。七つの定義を試験。 |
| ソース、リモート、導入先が異なった | 必須ツールを梱包。きれいなコミットからのマニフェストと ZIP を導入先と比較。 |
| Windows の読み書きが競合 | 共有読み取りと置換を共通化。一時ファイルでロック、再試行、旧値保持を試験。 |
| すべての測定で別サーバーを開始 | コードを削除。メインが既存ホストで使用量を取得し、Python が記録を読む。試験で測定中のプロセス起動を禁止。 |
| PATH が別の CLI を選択 | 測定経路から実行ファイル選択を削除。 |
| エラー出力が消えた | 子サーバーを廃止。診断はコード・種別・段階を最大 20 件保持し、予期しない Python エラーはローカル stderr に残す。 |
| 二つのループが毎秒全体を検証 | ハートビートは実行とエポックだけ、全体はコマンドと測定境界。 |
| 試験が模擬サーバーだけ | 受領記録の契約で試験。実結果を一時ファイルから読めることも過去に記録。 |
| ロール方針のしきい値が違う | `%10` を実際の `%20` に修正。測定不足で起動が拒否された場合に有効マーカーを解除。 |

`--usage-input` に原観測時刻と出典を渡します。監視は実行とエポックに紐付けます。ファイルの再読込や同じ値の再送で時刻は更新されません。欠落、未来、失効、時刻逆行、別実行を拒否します。更新されない場合は再試行して SAVE_AND_STOP を残します。

実測を更新するのはメインです。Python はホストを直接呼べません。`ingest` はデータ登録のみで、起動、許可、目標の観測、停止解除は別です。

通常と `-O` の重点テスト 111 件が記録されています。実 AGWF と Codex の起動を抑止し、ビルドと読み取り専用ツールが許可された子プロセスを使いました。ソース、導入ハッシュ、無効設定、きれいなソースでの再生成は個別に確認しました。

実使用量の応答を新しい受領記録経路で処理した際も、観測時刻を維持して新しいプロセスを起動しませんでした。アカウントや識別情報は梱包していません。過去の Remote 問題の厳密な原因は未確定で、実 AGWF/Remote の併用は試していません。[ネイティブ使用量の契約](../skills/agent-workflow-v1-1/references/native-usage.md)。
