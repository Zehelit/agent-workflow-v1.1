# 2026 年 10 月 28 日の AGWF 保守

> 過去の保守記録です。観測や許可は当時の作業に限ります。現在の動作は [README](../README.md) を参照してください。

六つのロールに個別の `agents/openai.yaml` と `allow_implicit_invocation: false` を追加しました。ロールは準備済みの AGWF 割り当てに限ります。割り当てや実際のモデルと推論値の証拠がない場合は停止します。ロールはワークフローや監視を起動しません。メインの文書は過去のプロジェクト選択を有効とする表現を削除しました。

Windows 状態ファイルの共有読み取り、権限を保持する置換、有限再試行をソースと導入先で揃えました。`candidate.py` も同じ読み取り方法を用います。外部の読み取りプロセスがロックしている場合は旧ファイルを維持します。ロックが続けばエラーを返します。

コンテキストと使用量のツールをパッケージ内の `tools/` に配置して、導入を作業コピーから独立させました。当時はソース、成品、導入先の 41 ファイルが一致しました。リポジトリルートの旧ツールとテストパスも整理しました。

保守記録ではパッケージ/ツール 63 件、Windows ファイルアクセス 9 件に合格しています。後者を `-O` とインストール済みのファイルでも実行しました。七つのスキル定義とハッシュを確認しました。ロール方針の欠落を検出したパッケージテストは修正後に合格しました。

保守中は AGWF と七つのスキルを無効にしたままでした。試験は一時ファイルでコアのアクセスを確認しました。実環境の Remote 併用は確認していません。

当時の残りの懸念は、測定ごとの別 Codex サーバー、PATH による CLI 選択、子サーバー stderr の破棄、全体検証の繰り返しです。最初の保守では Remote の原因を立証できませんでした。対応は[続きの記録](agwf-tum-duzeltmeler-20261028.md)にあります。現在の監視は二つ目の Codex サーバーを起動しません。
