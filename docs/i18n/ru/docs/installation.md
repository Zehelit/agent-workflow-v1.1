# Установка, проверка и сопровождение AGWF

Используйте Python 3.11 или новее и Git. Сборщик и кандидат используют стандартную библиотеку Python. Для установки выберите каталог навыков, доступный на запись нужному пользователю. Примеры команд рассчитаны на PowerShell. В Linux или macOS выберите соответствующий каталог в корне Codex, предназначенном для этого пользователя, и адаптируйте синтаксис оболочки. Проверки списков доступа Windows (ACL) относятся к этой платформе.

<a name="build-from-the-selected-checkout"></a>

## Сборка из выбранной рабочей копии

Выполняйте команды из корня репозитория AGWF. До приёмки сборки запишите исходный коммит и изучите локальные изменения. Каталог вывода должен быть новым.

```powershell
python --version
git rev-parse HEAD
git status --short
$build = Join-Path $env:TEMP ('agwf-build-' + [guid]::NewGuid().ToString('N'))
python -X utf8 -B tooling/build-candidate.py --output $build
if ($LASTEXITCODE -ne 0) { throw 'AGWF build failed.' }
$receipt = Get-Content -LiteralPath (Join-Path $build 'build-receipt.json') -Raw | ConvertFrom-Json
$pin = $receipt.manifest_sha256
$package = Join-Path $build 'agent-workflow-v1-1'
$entry = Join-Path $package 'scripts/candidate.py'
$manifest = Join-Path $package 'manifest.json'
```

Сборщик создаёт каталог пакета, детерминированный ZIP и квитанцию сборки. Принятую квитанцию храните вне изменяемого пакета вместе с подтверждением исходного коммита. Установщик ожидает принятый `manifest_sha256`. Хеш, заново рассчитанный после неожиданной правки, относится к другому наблюдению. [Привязка и установка пакета](../skills/agent-workflow-v1-1/references/coexistence.md).

<a name="choose-a-human-or-agent-path"></a>

## Ручная установка или установка через агента

Для каталога навыков текущего пользователя выполните следующие команды. Для пробной установки укажите изолированный каталог, оканчивающийся на `agent-workflow-v1-1`. Та же команда подходит для первой установки и проверки уже совпадающих файлов без перезаписи.

```powershell
$codexRoot = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$destination = Join-Path $codexRoot 'skills/agent-workflow-v1-1'
python -X utf8 -B $entry --manifest $manifest --manifest-sha256 $pin --version 1.1 install --destination $destination
if ($LASTEXITCODE -ne 0) { throw 'AGWF installation failed.' }
```

`activated:false` означает, что операция установила или проверила файлы без запуска рабочего процесса. В Windows временный каталог наследует права от родителя назначения. Под обычной учётной записью нужного пользователя проверьте возможность чтения и выполнения установленных файлов.

При установке через агента выполните следующие шаги.

1. Уточните назначение и вид установки: первая установка, обновление или изолированная проба. До изменения существующего назначения проверьте текущий пакет, пользовательские правки и принадлежащие установке процессы.
2. Проверьте исходный коммит и версию Python. Соберите в новый каталог и сохраните утверждённый хеш манифеста указанным выше способом.
3. Используйте установщик закреплённого кандидата с заданным назначением. Перед обновлением остановите только относящиеся к нему старые процессы и проверьте их выход. Если установщик откажет, существующее назначение останется для проверки.
4. Проверьте установленные манифест и файлы, затем выполните пассивную проверку из установленной точки входа. Сообщите исходный коммит, хеш манифеста, назначение и итоговый статус. Уточните, была ли это пассивная проверка или явно запрошенный действующий запуск.

<a name="verify-the-installed-entrypoint"></a>

## Проверка установленной точки входа

Возьмите новый временный проект и новый идентификатор запуска. Проверка запишет привязку в пробном проекте, не запуская процесс и не активируя цель.

```powershell
$probe = Join-Path $env:TEMP ('agwf-probe-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $probe -ErrorAction Stop | Out-Null
$installedEntry = Join-Path $destination 'scripts/candidate.py'
$installedManifest = Join-Path $destination 'manifest.json'
python -X utf8 -B $installedEntry --manifest $installedManifest --manifest-sha256 $pin --version 1.1 --project $probe --run-id install-check workflow validate
if ($LASTEXITCODE -ne 0) { throw 'AGWF binding validation failed.' }
```

Проверьте поля `identity`, `version`, `run_id`, `manifest_sha256` и `missing_dependencies`. В изолированной проверке для этой документации установка вернула `activated:false`. Валидация создала `run-binding.json` без файла состояния или каталога монитора. При неверном хеше манифеста команда завершилась кодом 2.

Следующий реальный вызов в Codex выполняется отдельно. Открытой сессии может понадобиться обновить каталог навыков. Явно выберите `$agent-workflow-v1-1` и укажите нужный объём. В [руководстве по эксплуатации](../skills/agent-workflow-v1-1/references/operations.md) описаны разрешённый запуск и проверка состояния монитора.

<a name="update-recover-or-remove"></a>

## Обновление, восстановление и удаление

- Перед обновлением управляемой установки остановите относящийся к ней процесс через прежнюю закреплённую точку входа и проверьте выход. Соберите и примите новый пакет отдельно. Добавляйте `--update` только для неизменённой управляемой установки. Правки пользователя сначала нужно учесть.
- Установщик проверяет временный пакет перед заменой и пытается восстановить прежний каталог при сбое размещения. Если и восстановление не сработало, сохраните каталог транзакции. Успешное обновление не оставляет постоянного архива отката. [Устройство установщика](../skills/agent-workflow-v1-1/references/coexistence.md).
- Другая техническая идентичность требует чистой установки в новый каталог. Храните прежние привязки с их исходными манифестами. Настройки обнаружения установленного навыка обработайте отдельно. После приёмки обновления начните новый запуск. [Границы миграции](../skills/agent-workflow-v1-1/references/migration.md).
- Команды удаления нет. Перед удалением подтвердите точный каталог навыка, остановите принадлежащие установке процессы и сохраните проверенную копию вне каталогов поиска навыков. Сохраните проекты пользователя, рабочее состояние, контрольные точки и внешние квитанции. После изменения проверьте обнаружение навыков.
