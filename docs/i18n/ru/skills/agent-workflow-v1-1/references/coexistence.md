# Закреплённая привязка среды и установка

Техническая идентичность — `agent-workflow-v1-1`, отображаемое имя — `agent-workflow-v1.1`. Неявный вызов отключён. Кандидат используется только при явном выборе. Модель в основном клиенте выбирает пользователь. Для ролей допускаются только `gpt-6.1-sol`, `gpt-6-astra` или `gpt-6.1-terra` с уровнем рассуждения не ниже `medium`. Внутренняя роль монитора закреплена на Terra/medium. Автоматическая замена исключена.

Текущий явный выбор требует, чтобы главный агент в том же ходе запустил и проверил работу в согласованном объёме. Выбор может повторно включить такой запуск после отключения. Прежний выбор и обслуживание пакета его не включают. Если подтверждения для полной активации отсутствуют или создание цели Codex запрещено, используйте ручной запуск монитора из [руководства по эксплуатации](operations.md). Не переходите к содержательной работе до подтверждённого запуска и не заменяйте её молча работой без мониторинга. Позднейшее указание остановиться имеет приоритет.

Для сборки используйте Python 3.11 или новее и стандартную библиотеку.

```powershell
python -X utf8 -B tooling/build-candidate.py --output C:/staging/build-one
```

Сборка создаёт `agent-workflow-v1-1/`, детерминированный ZIP и `build-receipt.json`. Сохраните `manifest_sha256` квитанции в принятых подтверждениях координации или передачи работы, вне изменяемого пакета. Этот внешний хеш передаёт вызывающая сторона как опорное значение доверия. Полная проверка манифеста и зависимостей предшествует привязке, существенной записи состояния рабочего процесса, шагам координации и каждому циклу замера. При публикации сигнала активности проверяется только запись управления запуском и эпохой, без полного обхода и хеширования каждую секунду. Пересчёт SHA изменённого манифеста и передача нового значения не подтверждают внешнее одобрение. Python проверяет байты и идентичность. Он не удостоверяет одобрение человека, метаданные поставщика или модели и файловую систему под контролем вызывающей стороны. Скомпрометированный интерпретатор или исполняемый файл и одновременная подмена привязки и принятого внешнего хеша выходят за рамки этих гарантий.

Глобальные параметры указываются до режима. Из исходников выполняют `skills/agent-workflow-v1-1/scripts/candidate.py` с манифестом сборки. Для установленной версии используют установленные `scripts/candidate.py` и манифест с тем же отдельно сохранённым хешем. Каждая привязка к исходникам или установке использует отдельный идентификатор запуска. Неизменяемая запись содержит разрешённые пути манифеста и зависимостей, проект, запуск, версию и хеши. Перенос запуска на другую программу, замена пакета, изменённые или отсутствующие зависимости или повтор запуска с другим хешем отклоняются. После утверждённого обновления начните новый запуск.

```powershell
$pin = '<preserved manifest_sha256 from accepted build receipt>'
$entry = 'C:/staging/build-one/agent-workflow-v1-1/scripts/candidate.py'
$manifest = 'C:/staging/build-one/agent-workflow-v1-1/manifest.json'
$common = @('-X','utf8','-B',$entry,'--manifest',$manifest,'--manifest-sha256',$pin,'--version','1.1','--project','C:/project','--run-id','candidate-run-1')
python @common workflow validate
python @common workflow status
python @common coordination --input C:/project/batch.json
```

Разрешённый `workflow activate` или `bind-active-goal` запускает монитор и проверяет первый исправный замер, переданный через `--usage-input`. `resume` открывает новую эпоху после действительного продолжения или проверенного технического восстановления по истёкшей квитанции при действующем разрешении на активную цель. Для этого нужна новая штатная квитанция. См. [эксплуатацию](operations.md) и [штатные замеры](native-usage.md). Для измерений не запускается сервер Codex или CLI. Активные команды продлевают срок работы. `complete` и `halt` останавливают и проверяют выход своего процесса Python. Явные команды `watcher` следуют тому же формату квитанции.

`workflow` принимает типизированные команды ядра и `validate`. JSON поступает через `--input` или стандартный ввод. В этом кандидате не поддерживаются прежние CLI ядра `native/install/export/migrate`. Разрешение `activate` и подтверждения `bind-active-goal` должны включать выбранный идентификатор запуска. `validate` проверяет роли и зависимости и привязывает пространство имён, не активируя цель. Формат пакета команд — `{ "batch_id": "inspect", "steps": [{ "key": "status", "command": "status", "payload": {} }] }`. Не более 64 шагов, пишет только главный агент, ожидающие исходы фиксируются на диске. Нет автоматического повтора или отправки через штатный инструмент. Рабочие команды требуют актуального типизированного разрешения и подтверждений приёмки. Конечное состояние сессии не означает приёмку. Устаревшую задачу, в которую уже не пишут, можно отклонить через `finish accepted:false`. При продолжающейся записи это невозможно. Для очистки требуется проверенная контрольная точка. История задач и записей о недействительности архивируется.

Изолированный корень расположен в `<project>/.agent-workflow-v1-1/runs/<run-id>/`. Корни рабочего состояния нельзя назначать задачам на запись. Встроенный монитор использует подкаталог `watcher/`, явно закреплённую программу расписания, неизменяемые данные принадлежности и аргументы повторного запуска через кандидата. Управление от чужого запуска или прямой вызов внутренней CLI не продлевают срок чужого процесса и не останавливают его. Неактивный чат не продлевает ограниченный срок. Выполняйте активную команду кандидата на границах работы. Обновление пакета не переносит работающие процессы автоматически. Отдельного навыка и пусковой программы монитора нет. Внутренние зависимости загружаются из одобренного пакета.

Для чистой установки, проверки без изменений и обновления укажите путь, оканчивающийся на `agent-workflow-v1-1`.

```powershell
python -X utf8 -B $entry --manifest $manifest --manifest-sha256 $pin --version 1.1 install --destination C:/staging/skills/agent-workflow-v1-1
python -X utf8 -B $entry --manifest $manifest --manifest-sha256 $pin --version 1.1 install --destination C:/staging/skills/agent-workflow-v1-1 --update
```

Для обновления нужны неизменившиеся байты управляемой установки. Установщик проверяет временный пакет перед заменой. При неудачной установке восстанавливается прежний каталог, при успехе материалы транзакции удаляются. Постоянного архива или команды отката нет. Если восстановление не удалось, каталог транзакции сохраняет единственную предыдущую копию для явного восстановления. Не удаляйте его до проверенного восстановления. Команды только подготавливают файлы, о чём говорит `activated:false`. Видимость в каталоге, реальный явный выбор навыка, метаданные эффективной модели поставщика и приёмка продукта в реальной работе проверяются после установки.

В Windows установщик сбрасывает права временного каталога до наследования от родительского каталога назначения до копирования файлов. Конкретная учётная запись не прописана. Другая или переименованная учётная запись получает права, уже заданные её родительскому `skills`. Родительский каталог должен разрешать чтение и выполнение нужному пользователю. После установки проверьте обнаружение навыка и прямое выполнение кандидата в обычной сессии Codex без повышения прав. Успех только в повышенной сессии недостаточен.
