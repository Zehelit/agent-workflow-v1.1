# agent-workflow-v1.1

只在用户为本次工作明确选择 agent-workflow-v1.1 时使用。禁用隐式调用。当前显式调用要求主代理在同一轮为授权范围启动 AGWF，包括准备或小任务。这可重新启用之前关闭的同一范围；历史选择或其他会话不算授权。讨论、引用、检查或维护技能不表示恢复已停止的工作。主会话负责交付、状态写入和所有真实派发。模型和推理力度由用户在客户端选择。启动后小任务可由主代理处理。组队可选，启动和监视不可省。

<a name="required-startup-on-explicit-invocation"></a>

## 显式调用后的必要启动

开展实际研究、编辑、测试或派发之前，取得新的原生用量回执，并通过固定版本的 candidate 启动。证据齐备时用获授权的 `workflow activate` 或 `bind-active-goal`。如果用户只授权准备、禁止创建原生目标或未提供活动目标，按[运行指南](references/operations.md)启动独立监视器，工作继续受授权范围限制。没有明确授权不得创建原生目标。仅加载技能、打开选择器或查一次配额不能代替启动。

确认所选运行与轮次的所属监视器存活，并有近期健康样本。完整工作流还要确认实际活动状态。开始实质工作前报告启动结果。现有健康运行与同一授权范围一致时应复用。停止后下一次明确调用可以授权受支持的继续或新轮次；保留真实用户事件并执行恢复检查。

启动被拒绝、证据不可得或达到 `SAVE_AND_STOP` 时，立即报告具体原因，仅执行必要的恢复准备。不要在主代理中悄悄接着做原任务。较新的停止指令优先。停止期间查看或更新技能不会继续之前的任务。

从固定 `scripts/candidate.py` 入口调用工作流命令、协调和监视。此入口也可在终端使用获认可的清单固定值直接运行，技能调用和监视命令都不是执行入口的前置条件。核心 CLI 直接调用会被拒绝。外部信任依据和运行隔离见[运行绑定](references/coexistence.md)，启动步骤见[运行指南](references/operations.md)。模型设置以角色 TOML 和 `private/limit-watcher/role.json` 为准。监视器实现、指令与角色一起打包并验证，未另设监视技能或启动器。

<a name="role-skills-and-memory"></a>

## 角色技能和记忆

各子代理有自己的 `SKILL.md` 和 `MEMORY.md`。协调、架构、实施、研究和验证位于 `roles/<role>/`，limit_watcher 位于 `private/limit-watcher/`。角色定义引用自己的文件。准备任务只加入对应角色的文件，文件缺失或为空则拒绝。临时专家继承基础角色文件以及该任务的专业说明。

每个角色技能只允许明确调用，作为已准备任务的内部指令。没有任务或与任务匹配的实际模型和推理力度证据时，报告缺口并停止。这些角色不启用工作流或监视。禁用 AGWF 要禁用七个技能项并停止所属监视进程。更新软件包不会重新启用。

角色记忆是持久的参考信息。它不授予权限，也不替代当前项目证据。不要杜撰历史。向主代理提出记忆更新，由它审查后在运行之间更新。角色文件在清单中，记忆变化也要走软件包更新和新运行绑定。实际工作期间不要修改安装目录。

<a name="integrated-limit-watcher"></a>

## 集成用量监视器

授权的 `workflow activate` 或 `bind-active-goal` 经固定入口自动启动无模型监视器。启动前从现有 Codex 连接取得真实 `mcp__codex_app__get_usage_limits` 回执，并通过 `--usage-input` 提交。详见[原生用量约定](references/native-usage.md)。监视器不会启动 Codex app-server、从 PATH 选 CLI 或连接其他通道。candidate 先确认健康新样本再写入活动状态，缺失或过期就拒绝。`resume` 需要新的回执和监视轮次。只有已记录的 `usage_receipt_expired` 停止可以用下面的技术恢复，其他停止需要明确继续或认可的原生状态转换。

主代理按自适应的 300/120/60/30 秒期限刷新回执。后台 Python 核验传入读数，没有新数据就关闭新工作，且无法主动调用宿主工具。重新读文件不会刷新观测时间。活动命令续租 600 秒。监视不健康时只能做恢复，不能继续新增工作。`complete` 和 `halt` 停止所属进程并验证退出。心跳只检查运行和轮次归属。完整哈希在命令与测量边界检查。工作阶段边界使用 `workflow status`。会话安静不会续租或更新测量。客户端不提供自动启动钩子。手动 `watcher start/ingest/status/renew/stop` 遵循相同回执与授权合同。

剩余 25% 时验证已完成工作的检查点。剩余 20% 或提前停止信号时停止新工作，请已开始写入的代理简短确认，核验必要文件，并只停止所属进程。用量缺失代表未知，重试一次，然后保存并停止。主代理收到 `SAVE_AND_STOP` 后无需等待代理即可行动。测量过期是技术中断，不能断言额度用尽或授权被撤销。停止并保存后，若记录为 `usage_receipt_expired`，可在同一已授权活动目标下用 `resume` 和 `usage_recovery: true` 恢复。所需证据包括真实新用量、同一目标的新观测、实际清单、未改变的检查点，以及所属进程已停止。candidate 在 `halt` 记录真实原因。额度、提前保留、其他故障、明确停止、非活动目标都不走此路。有证据就做技术恢复。不要仅因回执过期或未观测暂停而另要用户发一次继续。不要只因测量过期就把目标设为 `blocked`。依照原生目标工具本身的条件。恢复只恢复监视和辅助程序，不修改原生目标状态，也不生成用户引语或 UI 事件。其他停止仍适用其继续条件。不要自动兑换重置或修改目标。周窗口例外需要真实用户原话和有限有效期，保留两个窗口的观测。仅在判断有歧义时使用集成 `limit_watcher`，必须为 `gpt-6.1-terra`/`medium`；不可用时报告缺口。参见[运行指南](references/operations.md)和[监视顾问](private/limit-watcher/limit_watcher.md)。

有范围的状态交接遵循[上下文与验收约定](references/context.md)。保留原授权时间、固定证据和审查反证。摘要不会授权派发或证明缓存收益。原生执行结束与独立产物验收是两个版本化观测。重要独立审查前先执行无模型产物检查。

向子代理提供目标、必要输入、允许的写入路径和验收标准。使用新的上下文，不复制主会话。实施者按实际工作命名，例如 frontend、backend、editor 或 data_analysis。复用相关现有技能，不设无用常驻角色。需要特定领域时从基础角色创建临时专家，给定名称、领域指令、来源、工具和验收条件。无需预建领域角色或另行用户调用。

研究者收集并综合证据，实施者设计、构建和修复，验证者独立核验重要结果。只有高成本设计或技术争议才请架构设计者。机械重复工作使用脚本。优先复用合适脚本，必要时才建立并验证项目脚本。这由任务决定，不是后台空闲调度。没有常驻 Admin 或 Executor 层。

每个文件只有一位写入者。更改共用接口前先协调。涉及安全、认证、潜在数据丢失、共用 API 与大范围行为变更时独立核验。主代理可以自行验收范围小且易撤回的变更。返回结论、变更路径和证据，避免原始日志堆积。

遵守当前授权和项目限制。停止指令禁止继续派发，直至明确继续。保留当前工作与持久决定。只有恢复不再依赖时才清理由自己创建的临时材料。不要设任意字数限制或强制会议。

辅助程序仅验证经过自身的操作。它不会拦截原生工具或自动停止进程。主代理必须执行真实工具调用、记下结果并查看实际清单。没有提供者元数据，不要把请求的模型说成实际使用的模型。

<a name="coordination"></a>

## 协调

派发涉及相互依赖的专业领域的大任务前，请 `coordinator` 建议如何划分任务、安排依赖、选角色、划定文件归属和设定验收条件。范围显著改变、专家结论冲突未解或多次失败需要新计划时也应咨询。独立小任务和日常跟踪留给主代理。

提供目标、当前限制、发现和源码位置，并使用新上下文。协调者只返回只读计划，不派发、不写工作流状态。主代理审核授权和可行性，记录已接受任务并执行。依赖计划的任务通过 `depends_on` 关联认可的协调任务。小型容量和路径调整由主代理决定。只有重大策略问题才再次咨询。架构设计者负责技术设计，协调者负责组织工作。完成的会话无需等待，必要时另开范围明确的新任务。没有准确模型或推理力度时报告缺口，并暂停依赖计划的工作。仍可做已有独立授权的事。恢复不等待计划代理。

<a name="user-model-policy-27-october-2026"></a>

## 用户模型规则，2026 年 10 月 27 日

工作流角色只用 `gpt-6.1-sol`、`gpt-6-astra` 或 `gpt-6.1-terra`，推理至少为 `medium`。禁止 `none`、`minimal` 和 `low`。模型和默认力度以角色文件为准，禁止自动降级和替代。不要恢复已移除的 `astra_coordinator`。集成 `limit_watcher` 只用 `gpt-6.1-terra`/`medium`。主会话的模型和力度由用户决定。
