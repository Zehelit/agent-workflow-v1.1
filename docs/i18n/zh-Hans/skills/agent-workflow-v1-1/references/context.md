# 选择性提供当前上下文（N06）

`tools/render-active-run.py` 可从源码或已安装技能读取一次性项目或明确选择的项目。它不激活、刷新、迁移或写入工作流状态。用 `--as-of` 提供实际观测时间，保留原来源创建时间和轮次时间。稳定的 JSON 约定是 `context_version: 1`。状态、来源、引用和观测时间相同时，输出相同。

输出包括目标、当前身份、准确的当前授权或原生绑定、原来源和目标时间戳、当前目标观测、未关闭的任务约定及依赖和审查固定值、执行与验收观测、阻塞项及失效反证、改动产物哈希、证据文件引用与下一步。回执正文、准备好的提示词、完整报告、已完成会话的文字、转录和工具日志保留在原处。已验收任务的约定仍在固定的原状态里，摘要给出验收与精确证据引用。

引用是由 `{path, sha256, kind}` 构成的严格 JSON 列表，可包含 `task_id`。`kind` 取 `evidence`、`decision` 或 `counterevidence`。路径为精确且安全的项目相对文件路径，SHA-256 使用完整小写值。报告正文保留在源文件内。反证明确阻塞工作，直到主代理有意创建新的引用清单或修订。缩短摘要不能移除反证。缺少或过时的哈希、未固定且不支持的引用、缺少终态结果、未完成或已失效的依赖、拒绝或结果不明的工作，以及过时的目标、清单或用量，均为可见阻塞项。工具拒绝损坏状态、缺失依赖和无效固定值。

如果启用受保护的摘要模式，分配任务时将引用清单 JSON 本身固定为不可变的 `file_inputs`。`prepare.current_context` 仅由 `{path, sha256, manifest_path, manifest_sha256}` 组成。辅助程序对照类型化输入固定值单独读取清单，从当前状态和原始证据重建摘要并完整比对。重新固定缩短过的摘要不能去掉阻塞项或把旧引语当作新引语。摘要观测须在 0 至 60 秒内。准备会改写状态；应在 `dispatch-start` 前用同一个清单固定值生成新摘要。省略后续摘要或换掉清单会被拒绝。真实操作仍取决于授权、用量、原生身份、容量、准备参数和修订与哈希检查。渲染输出的 `dispatch_authorized` 始终为 false。

未启用 `current_context` 的命令仍按原有方式直接读取来源。摘要不授权调用原生工具。主代理要核验工具回执和原始人类授权；哈希只能证明字节相同，不能证明提供者身份。文件系统观测无法抵御任意外部进程并发写入，也不是原子快照。

`cache_status` 保持 `unknown`，`token_measurement` 保持 `pending_N08`。选择性上下文在此定义的是源码约定，尚未证明新原生子代理能重建上下文、缓存带来收益、节省 token 或已装环境采用了此流程。根据来源引用重建可操作状态，保留审查者的反证。

<a name="execution-and-acceptance-n07"></a>

# 执行与验收（N07）

`status.task_observations` 是基于 schema2 的只读 `contract_version: 1` 投影。它显示各任务的修订、观测到的执行状态、会话、时刻和新鲜度、独立验收、依据、审查者身份及写入归属。过时或缺失的原生执行观测归为未知。原生 done、idle 或 stopped 在新清单中释放执行容量，不能验收产物。待独立验收时，产物作者的写入权仍保留。可选的开放会话上限另行计算已观测的开放会话。

验证者固定已经停止写入的作者所对应的确切修订和产物哈希。审查不能直接或间接依赖同一作者产物先通过验收。审查运行时，作者仍待验收。流程在现有任务 `review` 字段记录已独立验收的验证者，并核对其独立会话、目标修订、输入约定和精确输出固定值。字节或修订变化后，恢复旧字节也不能使失效审查重新有效。早期 schema2 验收记录若缺少审查者关联，标为 `historical_unrecorded`，不会补认独立性。

独立性要求生产者与审查者的原生会话标识非空且不同，分配的审查哈希和记录的哈希一致。投影和依赖验收使用同一条件。历史不完整记录可作为 `historical_unrecorded` 读取，但不能让新依赖任务通过 prepare、record 或 dispatch-start。摘要标出 `DEPENDENCY_NOT_ACCEPTED`。准备完成后若审查者关系或原生身份丢失，实际派发也会被阻塞。不推断或自动迁移历史身份。

这是对现有可选字段的补充性投影，schema2 不变。旧格式被拒绝且不能导入。当前授权与已批准的运行绑定保持有效；摘要既不激活，也不替代它们。

<a name="producer-handoff-gate"></a>

# 产物交接检查

`tooling/check-producer.py` 是源码开发检查。用软件包附带的 Python 从工作副本运行 `-X utf8 -B`，分别在普通模式和 `-O` 模式运行。它需要源码测试，不能当作已安装的运行命令。申报变动路径和共用 API。固定测试选择器覆盖核心、输入、授权、目标、协调、上下文和验收的回归及反例，并重现 A04/A09/A11 已知边界。A11 历史运行器仅在临时源码副本的内存中根据 candidate 工作流固定值重新验证，历史文件本身保留；报告给出两处依赖固定值。此项检查不覆盖完整的监视器或浏览器测试。

机器结果固定所有已知 candidate 输入（源码、测试、角色）和所有申报变动文件的并集，包括固定列表以外的 Markdown。路径必须已存在且为规范的项目相对文件，拒绝遍历、绝对路径、盘符、别名、链接或越界。选定测试前后均计算并集哈希。申报文件有任何漂移就不能通过，`--expected-pins` 必须与整个并集相符。记录选择器、计数、失败和源码稳定性，并始终给出 `independent_acceptance: false`。测试失败、缺失选择器、固定值改变和无效拒绝元数据都会阻止通过。产物作者终止后，再对重要结果进行一次独立审查。

可选拒绝元数据仅有 `rejections` 和 `rework_seconds`。缺省时保留空观察列表与未知成本，而非填零。拒绝记录给出缺陷 ID 和类别、重现引用、一个修复者及对口审查者身份、修订和精确来源固定值。修复者不能审查自己的结果。同类问题再次被拒绝时，还记录简短的 `root_plan_correction`。总体计划由主代理负责，安排一个修复写入者和一次重点独立审查。不会自动增加架构师或团队。
