# 状态兼容性与恢复边界

v1.1 运行时只在获认可、不可变的运行目录内使用当前 schema2 状态。未知、损坏和旧格式会被拒绝，原运行状态不变。历史授权文本、归档任务回执和过期目标观测不授予权限。

固定入口 `scripts/candidate.py` 没有迁移命令。核心没有旧状态或授权转换器。从其他安装自动导入、引导或回滚均不受支持。接受更新后使用新的运行 ID。不要更改旧运行的清单或辅助程序对应关系。

当前恢复使用认可运行的已验证检查点和新的有效用户授权。保留来源时间戳、重放预留、文件完整性和写入已停止的观测。旧停止或继续文本只做历史记录。辅助程序不会自动激活恢复的目标。

新检查点归 `agent-workflow-v1-1` 所有。核心独立的默认状态目录是 `.agent-workflow-v1-1`，受支持的固定入口使用 `.agent-workflow-v1-1/runs/<run-id>`。旧 `.agent-workflow` 和 `.agent-workflow-v1-0` 不导入，仍是保留路径，不能用于任务或恢复。清理当前快照不会删除旧归属标识。直接调用核心 CLI 会被拒绝。

<a name="move-the-user-installation-to-the-11-technical-identity"></a>

## 将安装切换到 1.1 技术标识

1. 检查已有进程和写入者。只停止自己负责的运行。移动旧安装前验证对应进程确实结束。
2. 对照归属记录验证旧包。在所有技能扫描目录之外备份，检查哈希。先保留改动。
3. 使用新清单和外部固定值，把软件包首次安装到 `skills/agent-workflow-v1-1`。不要对旧技术标识用 `--update`。
4. 改变发现路径前，从新安装入口以全新的验证运行 ID 调用 `workflow validate`。比较返回的身份、版本、工作区和清单固定值。这样会写 `run-binding.json`，不会启动目标、工作流状态或监视器。
5. 新调用名是 `$agent-workflow-v1-1`。验证通过后更新 Codex 主技能与角色技能的路径，保留启用状态和显式调用设置。保护同时发生的配置修改。重新检查所属进程并保留其他会话仍在用的安装。安全切换后在技能扫描范围外归档旧包，再验证配置和备份。
6. 保留旧检查点、运行绑定和回执的标识、路径及哈希。用新包打开新运行。需要未完成的旧工作时，分别提供已验证的旧输出与当前实际授权。
