# 生命周期可靠性规范

> 2026 年 11 月 10 日的历史规范。观测和授权属于原任务。现有行为见[运行约定](../../../skills/agent-workflow-v1-1/references/operations.md)。

<a name="intended-result"></a>

## 预期结果

可靠地首次启用、刷新用量观测、从技术故障恢复和正常关闭。在目标开始运行前完成测试准备。首次启动、从已停止工作流恢复、计时分别报告。

<a name="evidence-available-at-the-time"></a>

## 当时的证据

- 旧私有计时报告记录，启用之前测量已过期。两次十秒试验分别以 98.74 秒和 45.05 秒失败。第二次启动新轮次并首次绑定，并未证明从原 halted 辅助程序恢复。
- 私有正常流程报告记录了健康启动，43.423 秒后获取新的真实测量、核验检查点、正常完成和进程退出。该次未出现 SAVE 锁定。
- 当时 `scripts/candidate.py` 可在 `resume` 创建新技术轮次，并在失败时恢复控制。首次 `activate` 或 `bind-active-goal` 没有同等重试日志，需要新的回归证据。
- 之前维护已解决授权与指令冲突，以及四处测试辅助和等待故障。回归测试需要保留这些行为。

<a name="requirements"></a>

## 要求

1. 仅针对同一目标、运行、范围内记录的首次 `usage_receipt_expired`，在取得真实新测量、实际活动目标观测及核实所属进程不存在后，用现有授权重试。不得要求新的用户引语或运行 ID，也不能改写用量证据。
2. 额度、提前保留、用户停止、目标非活动、进程归属不确定、包或证据变更及不同目标均拒绝。Python 核验结构和一致性，不认证调用方声称的用户或工具。
3. 失败尝试可追查，半启动不应显示为活动，不抹掉后来真实的 SAVE 记录。
4. 先准备包和试验，后取用量。保存真实观测时间。较新的文件不能刷新较旧观测。`ingest` 和续租分开。
5. 正常流程基于真实 `CHECKPOINT_SOON` 和 `SAVE_AND_STOP` 决定，不注入人为停止。
6. 原生 Continue 和真实活动后 halt 的恢复，单独于首次绑定证明。
7. 只有明确选择才计时。实际事件前准备好工具。迟到观测或错过期限不算通过。建议 SAVE 请求窗口为 10 ± 1 秒，报告实际时间。
8. 主代理调用宿主的原生目标工具。后台不增设未记录的工具访问、私有 Codex 通道或凭据读取。点击开始的准确计时需要真实原生事件来源。
9. 分别验证检查点、进程退出、工作流 complete 和原生目标完成。暂停需要用户授权，`blocked` 只能按原生工具条件使用。
10. 保留 Python 3.11+ 与标准库。Windows 共享故障不能作为进程退出或成功证据。保留本地改动和历史运行，不改写绑定。
